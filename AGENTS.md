# AGENTS.md — GiveMeJob!

> Этот файл читается агентом автоматически при работе в репозитории.
> Он задаёт правила, стек и порядок работ. Полная спецификация — в `docs/PLAN.md`.
> Если инструкция здесь противоречит `docs/PLAN.md` — приоритет у этого файла.

---

## 1. Что мы строим

**GiveMeJob!** — кроссплатформенное десктопное приложение (Windows/macOS/Linux), которое:

1. Агрегирует вакансии из десятков источников в единую нормализованную дедуплицированную базу.
2. Даёт быстрый гибридный поиск и фильтры по опыту/скиллам/зарплате/локации.
3. При открытии вакансии считает **честную калиброванную оценку вероятности** получить оффер именно этому пользователю на именно эту вакансию — с разбивкой по компонентам и планом закрытия пробелов.
4. Содержит AI-чат-агента с инструментами, который сам ищет по базе вакансий, подбирает под свободный запрос, объясняет карьерные направления и отвечает на вопросы.
5. Выглядит и ощущается как Notion: почти монохромный интерфейс, плотная типографика, ⌘K, мгновенные отклики.

## 2. Жёсткие инварианты (нарушать нельзя)

1. **Никогда не скрейпить LinkedIn и Indeed.** Только официальные API и публичные ATS-эндпоинты. Скрейпинг — только публичные career-страницы отдельных компаний, с уважением `robots.txt`, честным User-Agent и лимитом 1–2 req/sec на домен.
2. **Вероятность найма никогда не считается одной LLM.** Только гибрид: детерминированный компонентный скоринг → логистическое преобразование к базовой ставке → LLM-корректировка максимум ±0.15. См. `docs/PLAN.md` §4.
3. **В UI показывать диапазон, а не точку.** «18–27%», не «23%». Плюс дисклеймер и разбивка по компонентам.
4. **Ни один вызов LLM не идёт напрямую к провайдеру.** Только через `LLMRouter` с кэшем, локальным учётом квот и цепочкой фолбэков.
5. **Все ответы LLM — строгий structured output** по Pydantic/zod-схеме с валидацией. Никакого парсинга текста регексами.
6. **Тяжёлые вычисления — на этапе ingestion, не на клик пользователя.** Извлечение требований из вакансии делается один раз навсегда.
7. **В списке вакансий match-score считается локально, без сети и без LLM.** LLM-разбор — только при открытии карточки.
8. **Резюме пользователя не отправляется провайдерам, которые используют данные для обучения.** Для таких задач — локальная модель или явное согласие пользователя.
9. **Атрибуция источника и ссылка на оригинал обязательны у каждой вакансии.** Это требование бесплатных API (у Himalayas прописано прямо).
10. **Фазы 1→4 должны дать работающий продукт без единого вызова ИИ.** ИИ — надстройка, не фундамент.

## 3. Стек

### Десктоп
- **Tauri v2** (шелл; Rust только для файлов, keychain, автозапуск, автообновление)
- **React 19 + TypeScript + Vite**
- **Tailwind CSS** + CSS-переменные для темы (токены — в `docs/design-tokens.css`)
- **shadcn/ui** на Radix — компоненты
- **Motion** (ex-Framer Motion) — микроанимации
- **cmdk** — палитра команд ⌘K
- **TanStack Query** (серверный кэш) + **Zustand** (локальный UI-стейт)
- **TanStack Virtual** — виртуализация списков
- **SQLite** через `tauri-plugin-sql` + **FTS5** — локальный кэш и оффлайн
- **tauri-plugin-updater** — автообновление

### Бэкенд
- **Python 3.13 + FastAPI**
- **PostgreSQL 17 + pgvector + встроенный FTS**
- **Redis** — кэш LLM-ответов и учёт квот
- **ARQ** или **Celery** — периодические сборы и ретраи
- **httpx + selectolax** (статика), **Playwright** (только где реально нужен JS), **trafilatura** (извлечение текста)
- **Pydantic v2 + instructor** — валидация ответов LLM
- **sentence-transformers / fastembed** — локальные эмбеддинги `bge-m3` или `multilingual-e5-base` (1024 dim)
- **Alembic** — миграции
- **Sentry + structlog** — наблюдаемость

### Инфраструктура
- Docker Compose локально, VPS (Hetzner/Contabo) в продакшене
- GitHub Actions: линт, типы, тесты, контрактные тесты коннекторов, сборка десктопа под три ОС

## 6. Соглашения по коду

### Python
- Строгие типы, `mypy` в strict на `services/`.
- Никаких «голых» `except:` — всегда конкретные исключения.
- Все внешние HTTP-вызовы — через общий клиент с retry + exponential backoff + таймаутом.
- Один коннектор = один файл + один контрактный тест на зафиксированном фикстур-ответе.
- Никаких секретов в коде — только `.env` / переменные окружения.

### TypeScript
- `strict: true`, никаких `any` (используй `unknown` + narrowing).
- Никаких инлайн-хекс-цветов в компонентах — только CSS-переменные из токенов.
- Списки длиннее 50 элементов — обязательно виртуализировать.
- Оптимистичные обновления + skeleton-загрузка. Спиннеров и блокирующих модалок нет.
- Каждое действие, доступное мышью, должно быть доступно с клавиатуры.

### Общее
- Коммиты в Conventional Commits.
- Каждая новая фича — с тестом. Скоринг и дедупликация покрываются юнит-тестами обязательно.
- Не добавлять зависимость, если задача решается 30 строками кода.

## 7. Порядок работ

Идти строго по фазам. Не начинать следующую, пока не выполнен критерий выхода. Подробности каждой фазы — `docs/PLAN.md` §9.

| Фаза | Что | Критерий выхода |
|---|---|---|
| **0** | Монорепа, Docker Compose, миграции, CI, Sentry, ключи API | `docker compose up` поднимает всё, CI зелёный |
| **1** | Connector SDK + 5 API-коннекторов + ATS-слой + нормализация + дедуп + скиллы + планировщик | ≥50 000 живых уникальных вакансий, ≥60% со скиллами, ≥35% с зарплатой, медиана свежести <5 дней, дублей <3% |
| **2** | Локальные эмбеддинги, HNSW, гибридный поиск с RRF, FastAPI-эндпоинты | p95 поиска <200 мс на 200k вакансий |
| **3** | Tauri-скелет, дизайн-система, трёхколоночный лейаут, темы, ⌘K, SQLite-кэш, сборка+подпись+автообновление | Приложение стартует <1.5 с с данными из локального кэша, проверено на трёх WebView |
| **4** | Онбординг с парсингом резюме, схема профиля, детерминированный `fit_score`, бейджи и сортировка по матчу | Осмысленно отранжированная лента **без единого вызова ИИ** |
| **5** | LLMRouter, извлечение требований по всей базе, полная оценка вероятности, UI блока шансов, страница методологии | Оценка с диапазоном, разбивкой и планом пробелов; при исчерпании квот — деградация без падения |
| **6** | 8 инструментов агента, agent loop со стримингом, карточки вакансий в чате, память предпочтений, защита от инъекций | Агент сам находит вакансии по свободному запросу и объясняет выбор |
| **7** | Трекер заявок, сохранение предсказаний, дашборд конверсий, Platt scaling + Brier/ECE | Reliability diagram на странице методологии |
| **8** | Пустые/ошибочные/оффлайн состояния, производительность, онбординг за 60 сек, BYOK, лендинг, ToS, бета | 60 fps на 100k строк, RAM <250 МБ, закрытая бета на 20–50 человек |

## 8. LLM Router — обязательный контракт

```python
ROUTES = {
    "cheap_bulk": ["groq/llama-3.1-8b", "gemini/gemma-4-31b", "cloudflare/*"],
    "reasoning":  ["cerebras/gpt-oss-120b", "groq/llama-3.3-70b", "gemini/3.5-flash-lite"],
    "chat_agent": ["gemini/3.5-flash-lite", "groq/gpt-oss-120b", "openrouter/:free"],
    "local":      ["ollama/qwen3-8b"],
}
```

Порядок внутри `complete()`:
1. Проверить кэш по `cache_key(task, messages, schema)`.
2. Перебирать модели маршрута, пропуская те, чьи RPM/RPD/TPM уже исчерпаны по локальному счётчику в Redis.
3. Вызвать с таймаутом 25 с, провалидировать ответ схемой.
4. При `RateLimit | Timeout | SchemaError` — молча перейти к следующей модели.
5. Если все упали — локальная модель через Ollama.

Требования: TTL кэша разбора вакансии — бесконечный (вакансия неизменна); TTL кэша оценки — по ключу `(profile_version, job_id)`; батчить разбор по 10–20 вакансий за запрос; метрики по каждому провайдеру (успех / фолбэк / задержка / 429).

Актуальные бесплатные лимиты провайдеров (июль 2026) — `docs/PLAN.md` §3. **Их надо перепроверять раз в пару месяцев, они меняются часто.**

## 9. Дизайн — короткая версия

Полные принципы и токены — `docs/PLAN.md` §8 и `docs/design-tokens.css`.

- Контент главный, хром невидимый. Разделители 1px `rgba(0,0,0,0.06)`. Никаких градиентов и тяжёлых теней.
- Один шрифт (Inter / системный), 3–4 размера. Тело 14–15px, `line-height 1.5–1.6`.
- 90% интерфейса — оттенки серого. Цвет только для смысла.
- Текст `#37352f` (тёплый почти-чёрный), не `#000`.
- Переходы 120–160 мс с `cubic-bezier(0.16, 1, 0.3, 1)`.
- `border-radius` контейнеров ≤10px. Иконки строго 16px, Lucide.
- Управляющие элементы появляются на hover, а не висят постоянно.
- Хоткеи: `j/k` навигация, `s` в шортлист, `/` поиск, `⌘Enter` открыть в браузере, `⌘K` палитра.

## 10. Чего не делать

- Не парсить вакансии с машины пользователя — только центральный сборщик.
- Не складывать вакансии в контекст LLM «простынёй» — у агента есть инструменты.
- Не тащить Qdrant, пока не перевалило за ~5 млн векторов. `pgvector` в той же БД.
- Не гонять LLM по каждой вакансии для извлечения скиллов — сначала словарный матчинг, LLM только на остатке.
- Не давать агенту инструменты, меняющие что-либо кроме шортлиста. Никаких автоотправок заявок.
- Не расширять географию и вертикаль MVP. Одна география + одна вертикаль.
- Не заявлять точную вероятность как факт. Всегда диапазон + методология.
