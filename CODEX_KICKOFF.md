# Как скормить это Codex

## Вариант 1 — правильный (рекомендуется)

1. Создай пустую папку и git-репозиторий:
   ```bash
   mkdir givemejob && cd givemejob && git init
   ```
2. Распакуй архив в корень репозитория. Должно получиться:
   ```
   givemejob/
   ├── AGENTS.md
   ├── CODEX_KICKOFF.md
   └── docs/
       ├── PLAN.md
       ├── schema.sql
       └── design-tokens.css
   ```
3. Закоммить:
   ```bash
   git add . && git commit -m "docs: project plan and agent instructions"
   ```
4. Запусти Codex в этой папке (`codex` в терминале, или открой репо в Codex Cloud / расширении IDE).
   `AGENTS.md` подхватится автоматически — его не надо упоминать в промпте.

**Почему так.** Codex читает `AGENTS.md` из корня репозитория на каждом запуске и применяет его как постоянные правила.
Если просто вставить план в чат, он растворится в контексте через несколько сообщений. В `AGENTS.md` он живёт всегда.

---

## Вариант 2 — если Codex уже работает в существующем репо

Положи `AGENTS.md` в корень, `docs/` рядом, и один раз скажи агенту:

> Прочитай AGENTS.md и docs/PLAN.md, затем подтверди понимание кратким планом Фазы 0.

---

## Первый промпт для Codex

Скопируй целиком:

```
Прочитай AGENTS.md и docs/PLAN.md.

Выполни Фазу 0 (§7 в AGENTS.md, §9 в PLAN.md):
1. Создай структуру монорепозитория ровно как в AGENTS.md §4.
2. docker-compose.yml: PostgreSQL 17 + pgvector, Redis. Здоровые healthcheck'и.
3. Инициализируй Alembic и создай первую миграцию из docs/schema.sql.
4. Настрой services/api как минимальное FastAPI-приложение с /health.
5. Настрой apps/desktop как Tauri v2 + React 19 + TS + Vite + Tailwind + shadcn/ui,
   подключи docs/design-tokens.css как единственный источник цветов.
6. .env.example со всеми нужными ключами (Adzuna, Jooble, Groq, Google AI Studio,
   Cerebras, OpenRouter, Cohere, Sentry DSN, DATABASE_URL, REDIS_URL).
7. GitHub Actions: ruff + mypy + pytest для Python, tsc + eslint для фронта.
8. README.md с командами запуска.

Не переходи к Фазе 1. В конце покажи, как проверить, что всё поднимается.
```

---

## Дальше

Один запрос = одна фаза. После каждой фазы проверяй **критерий выхода** из таблицы в `AGENTS.md` §7.
Если критерий не выполнен — не двигайся дальше, доделывай.

Шаблон промпта для любой следующей фазы:

```
Фаза N выполнена, критерий выхода подтверждён.
Переходи к Фазе N+1 согласно docs/PLAN.md §9.
Соблюдай инварианты из AGENTS.md §2. Каждую новую функцию покрывай тестом.
```

---

## Что важно проверять за агентом

- Инварианты из `AGENTS.md` §2 соблюдаются? Особенно: вероятность **не считается одной LLM**, а UI показывает **диапазон**.
- Все вызовы LLM идут через `LLMRouter`, а не напрямую к провайдеру.
- Match-score в списке считается локально, без сети.
- У каждого коннектора есть контрактный тест на зафиксированном фикстур-ответе.
- Секреты только в `.env`, никогда в коде.
